# SEO Outsourcing Philippines

Website source and pre-launch preview. The current production website is WordPress; GitHub Pages is a separate static preview.

## Build and check

From `landing-page/`, run `npm ci`, `npm run build` and `npx tsc --noEmit`. The build generates both the standalone homepage and the WordPress homepage from the same React source. The original hero is protected by a regression fingerprint.

From the repository root, run:

```sh
node scripts/generate_au_pseo.cjs --check
python scripts/sync_wordpress.py --check
python scripts/version_assets.py --check
python scripts/check_site.py
python scripts/content_gate.py
python -m unittest discover -s tests -v
```

After changing curated Australian content or its base template, run `node scripts/generate_au_pseo.cjs`. After changing generated pages or the homepage, run `python scripts/sync_wordpress.py`. The WordPress import contains 67 drafts, including the discovery-call page. Importing does not publish them.

## Implementations

- `landing-page/`: editable React homepage, local fonts and assets.
- `standalone/site/`: 115 pages, all excluded from indexing pending release review.
- `standalone/backend/`: same-origin enquiry storage, notification recovery and private backup commands.
- `wordpress/sop-premium-agency/`: theme containing the same homepage design and shared page navigation.
- `wordpress/sop-proposal-form/`: WordPress enquiry form with administrator-only storage and notification retries.
- `quality/`: URL migration inventory, redirect mappings and release approvals.
- `tests/`: hero, copy, release, API, container and WordPress checks.

The standalone and WordPress implementations are alternatives. Follow [DEPLOYMENT.md](DEPLOYMENT.md) for the chosen platform. Do not replace the existing WordPress website with the static folder without completing URL migration.

## Preview

Run `python standalone/backend/serve.py --port 5182` for the website. Enable local form testing with `SEO_FORM_ENABLED=1` and keep `SEO_LEADS_DATA_DIR` outside the web root. No production mail credentials are included.

GitHub Pages is generated by `.github/workflows/pages-preview.yml`. It is non-indexable and cannot receive enquiries. Get a Quote opens a preview contact page with email and booking options; the backend form is not shown.

## Before production

`quality/release-approvals.json` remains on HOLD. No hosting credentials, mailbox tests, policy approvals or client permissions are inferred from passing code checks. The release builder validates signoffs, page links and the existing URL inventory before generating indexable files.

The sitemap inventory was retrieved on 10 November 2026: 76 page/archive URLs, 7 matching existing standalone paths, 21 redirect mappings and 48 paths subsequently retained. On WordPress, preserve existing posts, pages and archives. On standalone, the retained paths and redirects are validated before building a public release.

Never commit `.env`, live enquiry databases, backups or SMTP credentials.


## Standalone migration update

Standalone is the selected production platform. All 76 inventoried page/archive URLs are covered: 55 retained paths and 21 single-hop redirects. The 48 previously unresolved URLs are generated from saved public article text and category listings in `migration/preserved-content.json`. Run `python scripts/preserve_migration.py` to regenerate them and `--check` to verify synchronization. The standalone site now contains 115 pages; the optional WordPress draft import remains at 67.

This resolves URL mapping, not production publication approval. SMTP/inbox verification and the other business/hosting release checks remain required. The original hero is unchanged.
